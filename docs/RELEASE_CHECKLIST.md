# 后续发布检查

1. 在新目录建立明确的源码/资产白名单，审查 Git 暂存区；不打包开发目录、数据、环境、历史日志或 agent 状态。
2. 本地密钥扫描与个人路径/邮箱扫描，检查作者和提交者使用公开 noreply 身份；首发不导入开发历史。
3. 核对所有第三方代码、字体、模型、二进制与对应许可证/NOTICE；权重授权不明确时先取得明确授权或替换，不能用自己的 MIT 覆盖它。
4. 二进制分发另查 FFmpeg/LGPL 对应源码、库替换权利、Rust/数值库内嵌许可及微软运行库分发条件；源码仓库本身没有这些二进制，不等于后续安装器无需处理。
5. 跑源码与真正冻结程序的功能、安全边界、安装、升级、卸载、用户数据保留测试，并明确测试平台和没有验证的项目。
6. 对最终程序和安装器分别进行安全软件检查；确认来源、校验 SHA-256，并视发行需要进行代码签名。不得以功能通过、改名重打包或“杀软常误报”为安全结论，不关闭防护或加白名单来通过验收。
7. 未澄清的临时诊断程序告警只保留在本地审计材料，不把探针加入发行资产。二进制安全检查结果不应伪称独立认证。
8. 发布前检查公开 README、演示、附件、Actions 日志及 Release 文件，避免私人画面、原视频名、电脑路径、邮箱和真实密钥；完整许可证和必要源码随二进制保留。

本次是源码发布，没有附带旧安装器、模型或临时 EXE，也没有自动创建二进制 Release。
